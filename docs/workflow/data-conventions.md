# Соглашения об ID и данных

## Стабильные ID

- Каждая игровая сущность (предмет, враг, эффект, класс) получает постоянный ID, который НЕ совпадает с названием, показываемым игроку.
- Все ссылки между данными — только по ID. Ссылка по отображаемому имени запрещена.
- Почему это важно: отображаемое имя может меняться (правка текста, локализация). Если оно же является программным ID, переименование молча ломает ссылки между данными, и такая ошибка может долго оставаться незамеченной.

## Один авторитетный источник

- У каждой сущности ровно одна авторитетная запись. Остальные места ссылаются по ID, а не копируют значения.
- Числа баланса не дублируются вручную в документах: документы описывают смысл, таблицы при необходимости генерируются или проверяются из данных. Ручное дублирование рано или поздно расходится, и документ начинает противоречить данным.

## Граница «данные vs код»

- В данные выносится то, что настраивается без правки кода: числа баланса, составы волн, списки контента.
- Формулы и алгоритмы остаются в коде, пока не появится конкретная причина их вынести (например, настройка без пересборки). Шаблон НЕ предполагает, что все формулы будут жить в данных.
- Страница системы описывает смысл правил и указывает (через реестр), где живёт код; она не переписывает формулы.

## Формат и валидация

- Формат файлов данных — после выбора движка: подходящий нативный формат или переносимый (статус «TBD» в `testing.md`).
- Каталог `content/` создаётся вместе с первыми реальными данными, а не заранее.
